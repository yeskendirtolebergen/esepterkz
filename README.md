# Esepter.kz — готовность к публикации

Дата: 13 октября 2026 года.

## Вывод

Можно разместить как публичную демонстрацию на синтетических данных. Для реальных школ, персональных данных и достоверных экзаменов проект пока не готов. Архитектура и исходные файлы не изменены, ничего не удалено. Подготовлена отдельная копия для Vercel с настройками заголовков. Публикация не выполнялась.

## 1. Реальные технологии

- Frontend: HTML5, CSS, обычный JavaScript; SPA с маршрутами через `#`, без React/Next.js и без сборщика.
- Локализация: собственный `i18n.js`, русский/казахский/английский.
- Хранение: localStorage (`esepter-v1`, `esepter-language`). Это не серверная база данных.
- Внешние ресурсы: Google Fonts; при недоступности используются системные шрифты.
- Backend, API, Go, PostgreSQL, миграции, Docker, package.json и npm-зависимости отсутствуют в проверенной папке сайта.
- `.openai/hosting.json` содержит идентификатор прежнего Sites-проекта. Это не секрет и не конфигурация Vercel. В пакет публикации этот файл не включён.

## 2. Что проверено

- `node --check dist/app.js` и `node --check dist/i18n.js`: успешно, код возврата 0.
- Статическая раздача через временный HTTP-сервер: index.html, styles.css, i18n.js, app.js возвращают 200 и корректные MIME-типы; ответы совпадают с файлами.
- Отдельного production build нет: `dist/` уже является готовым статическим артефактом. Команда `npm run build` здесь неприменима. На Vercel Build Command и Install Command должны быть пустыми.
- Ограниченный поиск распространённых форматов секретов (приватные ключи, GitHub-токены, AWS access key, PostgreSQL URL) в папке сайта ничего не обнаружил. Это не гарантия отсутствия любых секретов; исходный код содержит публичные демонстрационные учётные данные.
- В этой проверке не выполнялись браузерные E2E-тесты и реальное развёртывание на Vercel. HTTP-заголовки из подготовленного конфига необходимо подтвердить после публикации.
- Backend и БД запустить/проверить невозможно: их реализации нет.

## 3. Безопасность и конфигурация

| Приоритет | Находка | Последствие / действие перед реальным запуском |

| Критический | app.js:17–20,73: правильные ответы, баллы и прогресс доступны и изменяемы в браузере | Результаты нельзя считать достоверными. Нужны серверная выдача вопросов, проверка ответов и запись попыток. |
| Высокий | app.js:46–47: chart() вставляет labels[i] в HTML; analyticsView() передаёт туда часть редактируемого имени | Потенциальная локальная stored DOM XSS при специально сформированном имени; требуется экранирование всех текстовых вставок и валидация данных. ## 4. Выбор хостинга

| Вариант | Для текущего проекта | Когда выбирать |
|---|---|---|
| Vercel — рекомендация | Простая публикация готового dist, HTTPS и домен, без постоянно работающего приложения | Демоверсия сейчас; frontend в будущем |
| Railway | Для этой статики дополнительных преимуществ немного; нужен способ её раздачи | Когда появятся постоянный backend и PostgreSQL; Railway предоставляет PostgreSQL-сервис |
| VPS | Технически подходит, но потребует настройки веб-сервера, TLS, обновлений, мониторинга и резервных копий | При конкретных требованиях к региону, инфраструктуре или полному контролю |

Для коммерческого проекта не рассчитывайте автоматически на Vercel Hobby: он ограничен личным некоммерческим использованием. Подберите подходящий тариф. Будущий хостинг данных учеников и домена .kz требует отдельной проверки требований к размещению; такая юридическая проверка в этот аудит не входила.

Источники: [Vercel static builds](https://vercel.com/docs/builds), [vercel.json](https://vercel.com/docs/project-configuration/vercel-json), [Vercel Hobby](https://vercel.com/docs/plans/hobby), [Railway PostgreSQL](https://docs.railway.com/databases/postgresql).

## 5. Переменные окружения

**Для текущей версии: обязательных переменных нет.** Файл `.env.example` содержит только комментарии. JavaScript в браузере не читает настройки окружения Vercel автоматически.

Ниже — возможные будущие имена, а не действующие настройки. Они появятся только после согласования и реализации backend:

| Имя | Назначение | Секрет |
|---|---|---|
| DATABASE_URL | Серверное подключение PostgreSQL | Да |
| SESSION_SECRET | Подпись сессий, если выбран соответствующий механизм | Да |
| APP_ORIGIN | Разрешённый адрес сайта | Нет |
| PORT | Порт сервера, если требует хостинг | Нет |
| SMTP_HOST / SMTP_PORT / SMTP_USER / SMTP_PASSWORD | Отправка писем, если добавлена | Пароль — да; остальные также хранить на сервере |

Сейчас добавление этих переменных ничего не подключит. Нельзя помещать секреты в dist или публичные переменные frontend.

## 6. Точные шаги публикации демоверсии на Vercel

1. Распакуйте `Esepter_Vercel_Ready.zip`. Корень проекта — папка, содержащая `vercel.json` и `dist/`.
2. Создайте отдельный GitHub-репозиторий и загрузите туда содержимое этой папки. Не загружайте весь рабочий каталог с документами и временными файлами.
3. В Vercel выберите **Add New → Project**, подключите этот репозиторий.
4. Установите **Root Directory** в корень репозитория (если загрузили папку целиком — выберите её). **Framework Preset: Other**; **Build Command: пусто**; **Install Command: пусто**; **Output Directory: dist**. Конфигурация vercel.json задаёт эти значения.
5. **Environment Variables: ничего не добавлять.** Выберите тариф, соответствующий использованию.
6. Нажмите **Deploy**. Это публикует только демоверсию. Откройте выданный адрес и `/#login`; проверьте RU/KK, вход демо-аккаунтом, кабинеты и тест. Убедитесь, что файлы app.js/i18n.js/styles.css загружаются без ошибок.
7. Проверьте ответ `curl -I https://ВАШ-ПРОЕКТ.vercel.app/`: должны присутствовать Content-Security-Policy, X-Content-Type-Options, X-Frame-Options и остальные заголовки. Просмотрите консоль браузера на CSP-ошибки. Конфиг CSP рассчитан на многофайловую dist-версию, не на однофайловый Esepter_UI_Preview.html.
8. Для домена: **Project → Settings → Domains → Add**. Укажите свой домен и внесите у DNS-провайдера именно записи, показанные Vercel. Дождитесь проверки DNS и выпуска HTTPS. Не меняйте MX-записи почты. [Инструкция Vercel](https://vercel.com/docs/domains/working-with-domains/add-a-domain).
9. После смены домена локальные данные старого адреса не перенесутся: localStorage привязан к origin. Проверяйте с чистой демоверсией. Обновления публикуются через новые коммиты; при проблемах вернитесь к предыдущему deployment.

Маршруты вида `/#login` обрабатывает браузер; catch-all rewrite для них не требуется. Не публикуйте однофайловое превью вместо dist под этим CSP.

## 7. Условия полноценного запуска

Нужны согласованные backend и БД, серверные роли/школы, парольное хеширование и защищённые сессии, работающая регистрация, серверное оценивание, устранение HTML-инъекций, резервные копии, мониторинг и проверка прав доступа. Это отдельная реализация, а не настройка хостинга; без разрешения архитектура не менялась.
